# 笔记写作规范

适用：系统讲解模式下写笔记、推导、例题和整理学习笔记；快答模式只沿用其中的检索命令与术语约定。全局工作流、两种模式与写入位置见 [AGENTS.md](AGENTS.md)。本文件维护写作细则；前置知识是否越界，由写完后的 `fpks-knowledge-check` 独立检查兜底，写作时仍按本文件自检。

## 一条逻辑线走完

- 讲解默认按系统学习材料组织：先说明要解决的问题与必要基础，再依次给出定义、推理、完整算例，最后回到原问题。每一步都要建立在前文已解释或已确认掌握的内容上。
- 一个文件只解决一条连贯问题线，从问题、前提、推演到结果形成闭环。系统性要求把这条线讲透，不以罗列相关领域或高级名词代替展开；与主线无关的内容不顺带介绍。
- 只有多条独立逻辑线或需要独立补充的前置知识才拆文件；不按篇幅硬切正在推进的推导。
- 篇幅服从系统性与可理解性，不设固定行数上限。不能为了简短而跳步、压缩前置知识，或把需要完整讲解的概念缩成一句术语说明；按逻辑拆分，不按长度拆分。
- 用具体算例把定义、操作过程与结果连起来，写出关键中间步骤，并解释这一步为什么成立。少用比喻和空泛总结。深度服从用户当前问题与学科局部规则。
- 若讨论明显偏离目标，简短提示并拉回主线。

## 组织与引用

新笔记写在对应学科目录中，frontmatter 带 `draft: true`。单篇能讲完时只写一个文件；需要多文件时组织如下。若是已有主题，沿用并优化其结构，而不是另起平行文件：

```text
<学科目录>/<主题名>/
  <主题名>.md      # 一条主线；多条独立题解时可作为索引
  <支线1>.md       # 需要补充的独立支线
  <支线2>.md
  assets/          # 绘图代码与最终图片
```

- 可复用的概念、定义、普适公式、定理、恒等式优先引用已有正式源笔记；库内没有合适来源时，再按独立复用的需要成卡。应用笔记通过块引用或已有块 ID 引用，本题特有的代数仍逐步写清。速查页需要就地展示原内容时，可用 `![[笔记名#^block-id]]` 块嵌入，避免维护第二份正文。
- **引用必须精确到具体的 callout 块（除非单个 callout 不足以体现完整上下文）**：使用 Obsidian 块引用语法 `[[笔记名#^block-id|显示名]]` 精准指向源笔记的 `[!def]` 或 `[!done]` 块；仅当需要指引读者阅读整节系统论证或对比多个视角时，才退回使用标题级链接（`[[笔记名#标题|显示名]]`）。
- **文件开头不写总括性语句，也不罗列链接**：不写“本页整理……”“本文讨论……”式的内容概述、摘要、来源说明、阅读路线或“前置参考：[[...]]”，开头直接进入定义、题面或推导；只保留后文确实依赖的记号约定和适用条件。引用必须由具体论证与推演驱动：只有在正文中推导演算、证明或展开真切用到具体定义、性质或定理时，才在该步骤精确引用对应的 callout 块。
- 为被引用的 callout 补充语义明确、稳定的块 ID（如 `^def-tensor-product-basis`、`^prop-mixed-product`），放在 callout 末行下方，保持命名清晰可读。
- “外置”指移出题解主干，另成一篇同样带 `draft: true` 的笔记。
- 引用用 Obsidian 双链；重名时用 `[[目录/笔记名|显示名称]]` 消歧。
- 不把 `draft: true` 笔记或旧 `DRAFT/` 中讲过的内容当作用户已掌握；必要前置知识需在本次解释中补足或链接到自包含支线。

## 术语与前置知识

- 先按下述 CLI 流程检索已有笔记中的定义与定理，判断哪些概念可以作为已有基础；检索范围排除各层级的 `DRAFT/`、`Clippings/` 和 `draft: true` 笔记。块类型只标记内容角色，掌握程度按笔记的掌握标记判断（见根目录规则）。
- 新主题从理解它所必需的基础讲起，不因用户提到一个名词就假定其掌握相关理论。每个必须使用的新概念，都要说明它解决什么问题、定义是什么、如何在具体例子中使用；只给名称或一句定义不算讲清楚。
- 必要前置知识能沿主线自然讲清时就原地展开；需要独立推导时另开自包含支线，并在首次用到前明确阅读顺序、接回主线的位置。本次解释依赖的支线应在本次写完整，不能只留一个待补链接。非必要概念直接省去。
- 少数关键术语首次出现时附英文，不用英文括号代替定义。
- 收尾前回扫专业名词。拿不准用户是否熟悉、正文是否解释过时，定向检索确认；搜不到则解释或改写。

## 定义与定理的 callout 结构

- **精要原则与篇幅控制**：callout 仅用于提炼最核心的定义公式、前置条件或定理结论，必须保持精练、克制，严禁将整节内容、大段铺垫、派生展开或具体计算全部塞入 callout。**严防“callout 篇幅远大于正文篇幅”**导致正文空洞、视觉失焦。正文是讲解和推演的主干，callout 只是提纲挈领、便于复用与检索的核心卡片。
- **块内外边界划分**：
  - **块内（精要）**：适用对象/前提假设、最本质的核心数学定义式或定理命题。
  - **块外正文（主干）**：背景动机、基底排序规则、分量/坐标展开细节、证明与推导、几何与物理诠释、算例与衍生讨论。
- **凡实际新定义一个概念、术语、量、运算、空间、关系或命名对象，其核心定义放在 `> [!def] 概念名称` 中。** 已有完整且适用的正式定义时，直接引用源笔记，不在新笔记中再建同一定义块；正文只说明本次选用的形式、符号或模型条件。题目里的临时变量赋值不必单独成块。
- **不是特别琐碎的定理、命题、引理、推论，以及可独立复用的重要性质、恒等式和判据，放在 `> [!done] 结论名称` 中。** 已有适用的正式结论时直接引用；本次新增或确有不同条件的结论，才在当前笔记建块，并把假设、适用范围和结论一起收入。题目特有的计算步骤、尚待证明的猜测、练习要求不冒充定理。
- 一个块表达一个概念或紧密相连的一组定义／结论。标题使用可检索的实际名称；原有编号、有限维等限定保留在标题或正文，不编码为 `Definition1B.2`、`done1` 等新类型。`notation` 中实际定义的对象也归入 `def`。
- 动机、证明、推导、例子和讨论接在块外，维持原有论证顺序；定义所必需的条件、符号含义不能散落到块外。不得只加一个空壳标题而把定义正文留在普通段落里。
- 块内每一行（包括空行和公式的 `$$` 行）都带 `>`；相邻块之间保留一个不带 `>` 的空行。默认展开，确需折叠时使用 `[!def]-` / `[!done]-`，不影响检索。
- 引用优先使用已有标题或块 ID；保留已有 `^block-id` 及双链目标。确需跨笔记精确引用时再补稳定的块 ID，不因格式转换改名、拆文件或删除原有内容。

```markdown
> [!def] 概念名称
> 定义适用的对象、条件，以及完整定义。

定义后的解释或算例。

> [!done] 定理／性质名称
> 假设与适用条件。
>
> 完整结论；需要单列的公式仍用带引用前缀的 $$ 块。

证明或推导。
```

## 用 Obsidian CLI 检索已有块

先按实际名称及常见中英文别名查同一块，以下为 PowerShell 可直接执行的命令（将 `causal` / `cosets` 换成当前关键词）：

```powershell
obsidian vault=FPKS search:context 'query=block:(/\[!def\]/ causal) -path:DRAFT/ -path:Clippings/ -[draft:true] -file:AGENTS.md -file:笔记写作规范.md' format=json
obsidian vault=FPKS search:context 'query=block:(/\[!done\]/ cosets) -path:DRAFT/ -path:Clippings/ -[draft:true] -file:AGENTS.md -file:笔记写作规范.md' format=json
obsidian vault=FPKS read 'path=DSP/Causal System.md'
```

- `search:context` 给出命中文件和行，**不保证返回整个 callout**；随后用 `read path=...` 核对完整块、上下文和该笔记 frontmatter 的掌握标记，再决定如何引用。只查已掌握笔记时可加 `[level:熟练]` 等属性条件。
- 未命中时，换名称／别名，并去掉 `block:(/\[!def\]/ ...)` 这一层，仅以关键词补查未结构化的正文，保留路径排除。不能把块检索无结果等同于库内没有该知识。
- 续写同主题时可单独检索 `[draft:true]` 或旧 `path:DRAFT/`；不要把这些命中混入已掌握知识。CLI 不可用时用 `rg` 定向补查，显式排除 `Clippings/` 和各层级的 `DRAFT/`，并核对命中文件的 frontmatter；读取旧草稿须加 `--no-ignore`，因为根目录 DRAFT 被忽略规则排除。
- CLI 用短参数完成检索和读取；批量格式校验直接读取本地文件。避免把长脚本或整篇笔记塞进 `eval code=...`、`create content=...` 等命令参数：本机 Windows CLI 已出现长参数触发主进程 JSON 解析错误的情况，参见 [同类问题的复现记录](https://forum.obsidian.md/t/cli-content-parameter-corrupts-multi-byte-utf-8-at-8-kb-chunk-boundary-silent/113867/5)。
- 本机命令入口为 `D:\programm\obsidian\Obsidian.com`；PATH 不可用时可用该完整路径。命令语法见 [Obsidian CLI](https://help.obsidian.md/cli)，块查询语法见 [Search](https://help.obsidian.md/Plugins/Search)。

## 数学与图片格式

- 短公式优先行内 `$...$`；长推导和需要单列的式子用 `$$...$$`，开闭的 `$$` 各自独占一行，公式块前后留空行。
- 保留 LaTeX，不把公式改成 Unicode、纯文本或代码块来规避聊天渲染问题。讲解的阅读载体是 Obsidian 文件。
- 分数不在指数中时用 `\dfrac`；指数中的分数可用 `\frac`。
- 表格单元格的公式不使用裸竖线 `|`，改用 `\vert` 或 `\mid`，避免拆列。
- 本地图片在笔记中使用相对于笔记文件的路径，如 `![说明](assets/example.png)`；不使用 `file:///`。保留对应绘图代码。
- **绘图排版与色彩对比规范**：严禁将多组复杂对比或多阶段推导硬挤在单张画板中导致字号缩水、细节模糊。涉及多个视点（如不同指标收缩方式、正反对比）时，必须拆分为多张独立、聚焦的图片分别绘制；正文文字、公式下标和标注必须设置足够大的字号。**严禁在浅色/白色底色上使用浅灰（如 `#999`、`#ccc` 等）低对比度字体**，所有次要标注、角标和未选中项文字均须采用高对比度深色（如 `#263238`、`#37474f` 或深色强调标记），确保在任何屏幕和光线下无需放大即可轻松认读。

## 结构样板：四道勒让德展开题

错误：主文件先讲四道题的一半，再把余下积分统一放到另一个文件，导致每一道题都没有闭环。

合适的组织：
```text
数理方法/勒让德展开计算技巧/
  勒让德展开计算技巧.md     # 索引和共同思路
  勒让德积分公式卡.md       # 若正式笔记已有则引用，不重复创建
  题1-多项式直接拆.md       # 完整题解
  题2-奇延拓平方.md         # 完整题解
  题3-绝对值型.md           # 完整题解
  题4-绝对值型.md           # 完整题解
```

每份题解写明目标函数，从展开到系数和结果核对完整走通；通用结果链接到公式卡，不省略本题计算。

## 交付前自检

- 按初学者顺序通读，检查是否出现“前置尚未解释，后文已在使用”；定义、推理、算例和原问题是否接成完整主线，关键计算与理由是否展开。
- 每个引入的概念都已讲清或有已确认的知识基础；没有顺带堆砌的高级名词，没有用多个浅尝辄止的分支充当系统讲解；草稿没有被误当作已知。
- 已通过 CLI 检索并阅读相关源笔记；已有完整且适用的定义、结论已直接引用，未仅因更换主题而重复建块。新增定义进入 `def`，新增重要结论进入 `done`，条件完整、标题可检索、正文未意外断块；符号和适用条件不同的内容没有仅因同名而合并。
- LaTeX 定界符、分数、表格竖线和图片路径符合上述约定。
- 文件开头没有总括性语句或链接罗列；每条双链都出现在实际用到它的步骤，并尽量精确到块。
- 双链目标存在，或已在本次任务中创建；重名链接可明确解析。
- 新笔记 frontmatter 带 `draft: true`，未改动任何掌握标记。
- 已执行 `fpks-knowledge-check` 并按报告修改；聊天只给文件链接、检查结果摘要与简短主线说明。
